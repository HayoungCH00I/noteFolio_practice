# 인수인계 — 합창단 및 로컬 HTTPS 카메라 공유

갱신일: **2026-11-18, Asia/Seoul**. 이번 갱신은 파일·Git 상태를 읽고 이 문서만 작성했다. 코드 수정, 인증서 설치·재발급, 서버 실행, 테스트·빌드 재실행은 하지 않았다. 기존 `docs/HANDOFF*.md`는 없었다.

## 1. 현재 목표와 완료 조건

Vite + vanilla TypeScript 실습 프로젝트의 **3주차 → 합창단**을 유지·개선하고, 같은 LAN의 다른 PC에서 HTTPS와 카메라로 이용할 수 있게 하는 작업이다. React/Vue 등 프레임워크를 도입하지 않는다.

**현재 활성 구현 요청이나 재현 중인 버그는 없다.** 마지막으로 다른 PC에서 카메라가 안 보이고 “양손 추적을 준비하지 못했어요”가 표시되는 문제가 있었으나, 사용자가 **“음 잠만 해결됨”**이라고 알려 원인 추적을 종료했다. 정확히 어떤 조치로 해결됐는지는 확인하지 않았다. 이미 진행 중이던 오류 처리 보완은 완료하고 검증했다.

기존 요구사항의 완료 기준:

- 합창단 4명, 4열 1행, 넓은 간격과 큰 좌우 흔들림. 카메라 영상 위에 단원과 나무 무대만 표시한다. 음표는 초기 구현의 2배이며, 불협화 상태에서는 찡그리는 표정이 나온다.
- 오른손 지휘 3종을 실제 합창 진행 시간 기준 약 10초마다 무작위 안내한다. 같은 모션의 연속 안내와 수동 선택 버튼은 없다.
- 왼손 엄지·검지 간격으로 실제 음높이를 바꾸고, 양손 주먹으로 정지, 정지 중 오른손 검지로 위아래 두 번 두드리면 3초 후 이어서 재생한다.
- BAD/SO SO가 3초 이상 지속되면 게임이 먼저 혼낼 단원을 강조하고 안내한다. 성공 또는 5초 경과 시 원래 지휘 안내로 돌아간다.
- 안내 문구는 중앙의 한 자리에서 상황에 맞는 것 하나만 표시한다. 멈춘 동안 일반 지휘 안내를 함께 표시하지 않는다.
- `npm run dev`는 LAN HTTPS로 동작하고, 인증서·비밀키는 `public`, 배포 산출물, Git, Vite 파일 제공에서 제외한다. 다른 PC용 인증서 자동 설치 ZIP을 제공한다.
- 기존 예제와 회사 WebSocket을 유지하고 테스트·빌드가 통과해야 한다. 실제 타 PC의 카메라·설치 프로그램 검증은 별도 미확인 사항이다.

## 4. 완료한 변경과 중요한 결정

### 합창단·음원·UI

- 현재 배치는 **4명 / 4열 1행**이다. 과거의 10명 / 2열 5행으로 되돌리지 않는다.
- 오른손 모션은 손 펴고 위아래(0.75배속), 검지·중지만 펴고 좌우(1.25배속), 검지·중지·약지를 펴고 원 그리기(1배속)다. 원 동작은 단순 대각선 왕복과 구분한다.
- 왼손 피치는 손 크기로 정규화한 엄지·검지 간격으로 ±6반음 조절한다. 약 0.55초 완화와 초당 최대 4반음 변화 제한이 있고, 모양을 풀거나 손을 놓치면 원래 피치로 돌아온다.
- 양손 주먹을 약 0.25초 유지하면 정지한다. 정지 중 오른손 검지로 수직 두 번 두드리면 효과음·지휘봉 연출과 3초 카운트 후 **멈춘 지점에서** 재개한다. 정지 중 검지는 혼내기로 해석하지 않는다.
- 수동 혼내기는 얼굴에 검지 끝을 약 0.35초 겹쳐 선택한 뒤 좌우로 흔드는 동작이다. 대상은 시무룩해지고 다른 단원은 그쪽을 노려보며 노래한다. 표정 연출은 약 4.5초 지속한다.
- 자동 혼내기는 **실제로 노래 중이고 BAD/SO SO가 3초 지속될 때** 먼저 안내한다. 사용자가 검지를 펴야 안내가 시작되는 방식이 아니다. 4명 중 무작위 대상만 선택 가능하게 제한한다. 안내 중 일반 지휘 채점과 모션 변경은 쉬며, 성공 또는 5초 경과 후 지휘 안내로 복귀한다. 종료 후 합창 진행 시간 기준 15초 재안내 간격이 있다. 기존 수동 선택/혼내기를 진행 중이면 자동 안내가 끼어들지 않는다.
- 카메라는 전체 화면 배경이다. 별도 오른쪽 패널은 없다. 피치 막대는 왼쪽, 카메라 버튼은 오른쪽 위, 합창 시작은 오른쪽 아래다.
- 평가 색상은 **BAD 짙은 파랑 / SO SO 하늘색 / NICE 노랑 / EXCELLENT! 빨강**이다.
- 왼손·오른손·양손 주먹 안내는 왼쪽 위에 가로로, 가운데 손과 같은 반투명 SVG 그림과 기존 두 배 크기 글씨로 표시한다. 모든 상황별 게임 안내는 중앙의 한 자리에서 교체한다. 멈추면 “노래를 잠시 멈췄어요.”만 나오며 일반 지휘 문구·손 애니메이션은 숨긴다. 진행 시간 옆의 중복 모션 설명도 제거했다.
- 사용자 제공 음원은 **`public/music.mp3`**, 선택 구간은 **0:18~1:52, 원본 기준 94초**다. 이 파일의 존재를 이번 읽기 점검에서도 확인했다. 재생 속도와 정지에 따라 실제 플레이 시간은 달라진다.
- YouTube 링크 `64fwAdHw18I`는 원곡 참고 정보다. **현재 재생은 YouTube iframe이 아니라 로컬 MP3**다. YouTube iframe으로는 요구한 실제 피치 조절을 할 수 없어 전환했다.
- `@soundtouchjs/audio-worklet` **2.1.1**을 사용해 속도와 피치를 분리한다. 음원은 지정 구간만 잘라 AudioWorklet에 전달한다. 원본 합창 녹음을 사용하는 연출이며 개별 단원 목소리 합성은 아니다.

### 카메라·추적 오류 보완

- 기존 하나의 `catch`가 카메라 획득·영상 재생·모델 초기화 오류를 모두 “양손 추적을 준비하지 못했어요”로 표시하고 영상을 껐다. 이 문구만으로 실제 원인을 판단할 수 없었다.
- 현재는 장치/권한/영상 재생 오류와 손 추적 초기화 오류를 구분하고 원래 오류 정보를 남긴다. 워커와 기본 방식 모두 실패하면 `AggregateError`로 두 오류를 보존한다.
- 손 추적만 실패하면 **카메라 영상은 유지**하고 중앙에 **손 추적 다시 시도** 버튼을 제공한다. 카메라를 다시 요청하지 않고 추적만 재시도한다. `trackingReady` 전에는 게임 시작을 비활성화한다.
- `OverconstrainedError`일 때만 카메라 제약을 완화해 한 번 재요청한다. 권한 거부는 자동 반복 요청하지 않는다. 영상은 muted/playsInline로 재생한다.
- 페이지 이탈·장치 종료·늦게 도착한 권한 응답에 대한 세대 토큰과 자원 정리를 유지한다. 손 추적은 최대 초당 20회, 동시에 한 프레임만 처리한다.
- MediaPipe는 `@mediapipe/tasks-vision` **1.2.3**이며 동일 버전의 WASM 파일이 `public/mediapipe/wasm/`에 있다. 합창단은 손 모델만 로드하고 GPU 실패 시 CPU, 워커 실패 시 기본 스레드로 대체한다. 카메라 프레임을 서버로 업로드하지 않는다.

### LAN HTTPS·인증서 설치 자동화

- Vite 개발 서버는 `host: 0.0.0.0`, 기본 포트 5173, HTTPS이며 자동 브라우저 열기는 껐다. 기존 ES 워커와 회사 WebSocket 플러그인을 유지했다. 회사 클라이언트는 HTTPS에서 기존 코드로 `wss://`를 사용한다.
- `npm run build`와 기존 미리보기는 개발 인증서가 없어도 동작하도록 유지했다. 별도 `npm run company` 서버(4173)의 설정은 변경하지 않았다.
- 마지막 확인된 LAN 주소: **`https://172.30.1.23:5173/#eleventh`**. IP와 포트는 현재라고 가정하지 말고 재확인한다. 포트 사용 중에는 Vite가 다음 포트를 선택할 수 있다.
- mkcert로 `localhost`, `127.0.0.1`, `::1`, `172.30.1.23` SAN을 가진 인증서를 발급했다. 인증서·비밀키는 `.certs/`에 있고 디렉터리 권한 700, 키 권한 600으로 제한했다.
- `.gitignore`에 `.certs/`, `*.pem`, `*.key` 제외를 추가하고 Vite의 기본 민감 파일 차단을 보존하면서 `.certs/**`도 차단했다. 비밀키와 인증서를 `public`이나 `dist`로 복사하지 않는다.
- **같은 Wi-Fi와 HTTPS 링크만으로 상대 PC의 인증서 신뢰가 생기지 않는다.** 웹 링크가 아니라 상대방이 설치 파일을 한 번 실행하는 방식으로 설치 과정을 자동화했다. 보안 승인·관리자 비밀번호 입력·카메라 권한은 상대방이 처리한다.
- `.certs/client-setup.zip`에 공개 `rootCA.pem`, `Mac-HTTPS-Setup.command`, `Windows-HTTPS-Setup.cmd`, `README.txt`만 포함한다. 인증서 해시를 검증하며 서버키·CA 비밀키는 포함하지 않는다. 깨끗한 임시 스테이징 폴더에서 ZIP을 만들어 기존 폴더의 임의 파일이 섞이지 않게 했다.
- Mac 설치 파일은 관리자 승인을 거쳐 시스템 키체인에, Windows는 현재 사용자 루트 저장소에 등록한 뒤 공유 주소를 연다. 상대 PC에 mkcert/Node.js 설치는 필요 없다. ZIP 생성기는 **현재 호스트인 macOS의 ditto**를 사용한다.
- `npm run certs`로 IP를 포함해 재발급한다. `npm run certs:clients`로 ZIP을 만든다. 포트가 다르면 `npm run certs:clients -- https://172.30.1.23:5174/`처럼 실제 주소를 지정한다. IP/포트/CA 변경 후에는 이전 ZIP의 주소·인증서가 맞는지도 확인한다.

## 5. 커밋되지 않은 변경사항

Git 저장소가 없어 **커밋 대비 diff나 미추적 파일 목록을 확정할 수 없다.** 아래는 대화에서 작업했고 현재 파일로 확인되는 주요 결과물이지, Git diff 목록은 아니다. 원본 상태로 일괄 복구하거나 Git에 올라갔다고 가정하지 않는다.

- 통합 파일: `src/main.ts`, `src/pages.ts`, `src/style.css`, `src/fruit-tracker.ts`, `src/fruit-vision.ts`.

## 6. 실패한 시도와 관찰 결과

1. **`mkcert -install` 자동 신뢰 등록 실패:** mkcert 설치와 CA 생성은 성공했으나 `security add-trusted-cert`가 sudo 비밀번호/TTY 필요로 종료했다. 이후 사용자가 직접 등록했는지 이 Mac의 OS 신뢰 상태는 확인하지 않았다. 발급 자체는 완료했고 설치 명령과 다른 PC용 자동 설치 ZIP을 제공했다.
2. **다른 PC의 인증서 경고:** 사용자는 처음 ZIP을 실행하지 않은 상태였고, Mac 브라우저 사진에 빨간 “주의 요함”, HTTPS 취소선, “보안 경고를 끄기로 설정”이 보였다. 사이트 카메라 권한은 켜져 있었다. 경고 무시와 루트 인증서 신뢰 등록은 다르다는 점을 안내했다.
3. **서버 문제 여부 확인:** 당시 이미 실행 중인 서버에 지정 CA를 사용한 HTTPS 클라이언트 요청으로 HTTP 200, TLS 검증 성공, 현재 프로젝트 인증서와 지문 일치를 확인했다. 이는 **지정 CA를 사용한 검증**이지 모든 PC/브라우저의 OS 신뢰 등록을 증명하지 않는다. 에이전트가 새 서버를 실행한 것은 아니다.
4. **손 추적 준비 실패:** 당시 `/mediapipe/models/hand_landmarker.task`, WASM JS/바이너리 두 변형, 합창단 워커 경로가 모두 HTTP 200이었다. 서버에서 파일을 못 찾는 문제는 관찰되지 않았다. 사용자 PC의 실제 예외 정보는 확보하지 못했다. 사용자가 해결됐다고 알려 추적 종료했으므로 **원인을 인증서·GPU·다른 앱 점유 등으로 확정하지 않는다.**
